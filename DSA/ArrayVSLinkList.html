Arrays & Linked Lists — In-Depth Study Guide

This is a deeper version designed for exam preparation. It contains formal definitions, types, memory layout, algorithmic complexities, detailed operations (with code examples), common pitfalls, typical exam questions, and practice problems.

1. Formal Definition — Array

An array is a data structure that stores a fixed-size sequential collection of elements of the same type in contiguous memory locations. Each element can be accessed directly using its index (offset) from the start address.

1.1 Memory Layout

Elements are placed consecutively in memory. If each element is size S and array starts at address A, element at index i is at address A + i * S. This allows constant-time indexing.

1.2 Types and Variants

  • Static arrays — allocated with fixed size (e.g., int a[10] in C).
  • Dynamic arrays — growable arrays backed by contiguous memory; resizing usually doubles capacity (e.g., std::vector, ArrayList, List<T>).
  • Multi-dimensional arrays — arrays where each element is itself an array (e.g., matrices).
  • Sparse arrays — optimized for arrays with many empty elements (use maps/hashes to store non-empty entries).

1.4 Resizing Strategy (Dynamic Arrays)

Common strategy: when array is full, allocate a new array with larger capacity (commonly double), copy old elements, free old array. Amortized insertion complexity becomes O(1).

    array = newArray
  array[size] = value
  size++

2. Formal Definition — Linked List

A linked list is a linear collection of nodes where each node contains data and one or more pointers (references) to other nodes. Unlike arrays, nodes are not contiguous in memory.

2.1 Types of Linked Lists

  • Singly linked list — each node contains data and a next pointer to the next node.
  • Doubly linked list — nodes contain next and prev pointers.
  • Circular linked list — last node's next points back to the head.
  • Sentinel / Dummy nodes — special nodes to simplify boundary cases (head/tail management).

2.2 Node Structure

// Singly Node (C#)
public class ListNode {
  public int val;
  public ListNode next;
  public ListNode(int v){ val = v; next = null; }
}

2.4 Memory Layout & Overhead

Each node stores data plus one or more pointers. Pointer overhead depends on the architecture (32-bit vs 64-bit). Also, nodes often require separate heap allocations which increases fragmentation and decreases cache locality.

3. Detailed Operations — Arrays

3.1 Insertions

To insert at index i, shift elements from i..n-1 one position to the right, then place the new value. Cost: O(n-i) → O(n) worst-case.

3.2 Deletions

To delete at index i, shift elements from i+1..n-1 left by one. Cost: O(n).

3.3 Traversal

  • Two-pointer technique (fast/slow) in arrays for partitioning problems.
  • Prefix sums for range-sum queries.
  • Sliding window for subarray problems.

4. Detailed Operations — Linked Lists

4.1 Insertion at head (singly)

function insertHead(head, value):
  node = new Node(value)
  node.next = head
  head = node
  return head

4.2 Insertion at tail (maintaining tail pointer)

function insertTail(head, tail, value):
  node = new Node(value)
  if head == null: head = node; tail = node
  else: tail.next = node; tail = node
  return (head, tail)

4.3 Deletion (given value)

Traverse keeping previous pointer; when node matches value, previous.next = current.next. Special-case when deleting head.

4.4 Reverse a singly linked list (iterative)

function reverse(head):
  prev = null
  curr = head
  while curr != null:
    next = curr.next
    curr.next = prev
    prev = curr
    curr = next
  return prev

4.5 Detect cycle (Floyd's Tortoise and Hare)

function hasCycle(head):
  slow = head; fast = head
  while fast != null and fast.next != null:
    slow = slow.next
    fast = fast.next.next
    if slow == fast: return true
  return false

4.6 Merge two sorted linked lists

function merge(l1,l2):
  dummy = new Node(0)
  tail = dummy
  while l1 != null and l2 != null:
    if l1.val < l2.val:
      tail.next = l1; l1 = l1.next
    else:
      tail.next = l2; l2 = l2.next
    tail = tail.next
  tail.next = l1 != null ? l1 : l2
  return dummy.next

6. When to choose which?

  • Choose array when you need random access, want better space efficiency, or are working with fixed-size data and numerical computations.
  • Choose linked list when you need many insertions/deletions at the ends or when you need constant-time insertion/deletion and don't need random access.
  • Consider alternatives: balanced trees, hash tables, deques, skip lists, dynamic arrays, and specialized structures (rope, B-tree) depending on constraints.

10. Tips for Exams

  • Memorize complexities for common ops (access, insert, delete) for both arrays and lists.
  • Practice writing code by hand for linked list pointer operations — off-by-one or null-pointer errors are common pitfalls.
  • When asked to choose a DS, mention memory, speed, and typical operations required by problem.
